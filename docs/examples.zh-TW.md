# 提示詞範例

[English](examples.md) · [返回 README](../README.zh-TW.md)

在**目前的主 Task** 貼上提示詞。把中括號內的內容換成你的實際工作與驗收條件。只要明確要求另開 Codex Task，模型就可以依已安裝 skill 的描述選用它；不必寫出 skill 名稱。這是模型的選用判斷，不是每次建立 Task 都必定執行的鉤子。

## 你剛剛的用法

你在本次對話中直接說：

```text
將這個Task當主代理Task 建多GPT-6 Luna Task 委派與排程器實驗驗證
```

這句話已表達「另開多個 Task」、「目前 Task 當主代理」與「要驗證排程」，不必加上 skill 名稱。若是一般工作，可以把實驗目標換成具體交辦內容與驗收條件：

```text
請將目前這個 Task 當主代理，另開兩個 GPT-6 Luna Codex Task，分別處理[工作 A]與[工作 B]。目前 Task 負責整合與驗收；每個受託 Task 各有一個專屬監控排程。請依工作階段調整各自的檢查間隔，最長不超過 30 分鐘；沒有新進度時保持安靜，驗收完成後停用對應排程。
```

## 1. 委派一個新 Task，由主 Task 負責驗收

```text
請另開一個 Codex Task，交辦它完成[具體工作]，範圍限於[檔案或模組]；完成條件是[可檢查的成果或命令]。目前這個 Task 保留整合與驗收責任。請確認新 Task 已開始，並為它建立一個專屬監控排程；依實際成果更新檢查節點，驗收完成後停用排程並向我報告。
```

## 2. 同時委派兩個 Task，分別監控

```text
請另開兩個 Codex Task：第一個負責[工作 A、範圍、驗收條件]；第二個負責[工作 B、範圍、驗收條件]。兩者不要修改相同檔案。由目前 Task 整合與驗收。每個受託 Task 各有自己的監控排程；由主 Task 依下一個有意義的檢查點選擇並調整間隔，最長不超過 30 分鐘，沒有實質變化時保持安靜。請不要把兩個 Task 合併到同一個排程，也不要讓受託 Task 管理排程。
```

## 3. 續接已存在的 Task

```text
請續接這個既有 Codex Task：[貼上 codex://threads/... 連結]。它原本受託處理[目標]，目前已完成[已驗證的進度]，還需[下一步與驗收條件]。目前 Task 繼續負責驗收。請先讀它的狀態與成果；若已有專屬監控排程，就更新原排程，不要新建重複的 Task 或排程。
```

## 4. 新 Task 交由自己追蹤

```text
請另開一個獨立的 Codex Task 處理[具體目標與驗收條件]。我會直接在新 Task 追蹤和續談；目前 Task 只需確認它已開始並給我連結，不用替它建立監控排程。
```

## 5. 明確要求不排程的委派

```text
請另開一個 Codex Task 完成[具體工作與驗收條件]，由目前 Task 負責最後驗收。這次不要建立定時監控排程；請在目前回合使用可用的等待工具追蹤，必要時再讀取受託 Task 的成果。
```

## 協調 Task 發給受託 Task 的訊息

以下是**協調 Task 實際送出的訊息**，不是使用者必須額外輸入的提示詞。首則 `create_thread` 訊息還不知道新 Task ID，因此先說明雙方關係：

```text
委派關係：協調 Task 是 [已知的協調 Task ID 或連結]，負責整合、驗收與監控排程。這則訊息的收件者是新建立的受託執行 Task，負責 [工作範圍]；新 Task ID 由平台建立後提供。
交辦工作：[具體目標]。完成證據：[可檢查的成果]。請回報成果與阻礙，由協調 Task 驗收。
```

後續用 `send_message_to_thread` 發訊息時，雙方 ID 都已知；訊息中的受託 Task ID 必須與工具的目標 ID 相同：

```text
委派關係：協調 Task [協調 Task ID] 是發送者，負責整合、驗收及監控排程；受託執行 Task [受託 Task ID] 是這則訊息的收件者，負責 [工作範圍]。
請處理 [精確的下一步]，以 [證據] 回報。協調 Task 將檢查結果。
```

排程提示也要明示收件者與監控對象：

```text
排程喚醒的收件者：協調 Task [協調 Task ID]，負責檢查及驗收。唯一監控對象：受託執行 Task [受託 Task ID]，負責 [工作範圍]。請先讀取受託 Task 的最新狀態與成果，再決定下一步。
```

跨 Task 訊息不要用「本 Task」指稱協調者，因為收件者讀到時可能把它理解成自己。

建立新 Task 不等於一定要替主 Task 建排程：是否監控，取決於目前 Task 是否仍負責追蹤與驗收，以及你的明確指示。這些提示詞不保證模型會一直在背景執行；排程實際喚醒後能否自動依狀態推進，仍以[驗證紀錄](verification.md)所列的證據為準。
